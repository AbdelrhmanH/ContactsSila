# ADR-0001: KMP لمشاركة المنطق مع واجهات أصلية منفصلة
- **الحالة:** مقبول
- **التاريخ:** 2026-10-25

## السياق
التطبيق يعتمد بعمق على واجهات النظام (جهات الاتصال، المكالمات، الإشعارات، الحظر)، ونريد تجربة أصلية 100% على أندرويد و iOS، مع تجنب كتابة المنطق مرتين.

## القرار
- **Kotlin Multiplatform** لـ: النماذج، UseCases، Repositories، Room، DataStore، Ktor، Firebase، والـ **ViewModels**.
- **Jetpack Compose** لأندرويد و **SwiftUI** لـ iOS.
- الوصول لقدرات النظام عبر واجهات في `core:platform` تُنفذ لكل منصة (expect/actual أو حقن تنفيذ Swift).
- **SKIE** لتحسين التوافق مع Swift.

## البدائل المرفوضة
- **Compose Multiplatform للواجهة:** أسرع، لكن التجربة على iOS أقل أصالة — رُفض بطلب صريح.
- **Flutter / React Native:** لغة مختلفة وتكامل أضعف مع واجهات النظام العميقة.
- **تطبيقان منفصلان بالكامل:** ضعف التكلفة والأخطاء.

## العواقب
- ✅ منطق واحد مختبر، واجهات أصلية.
- ⚠️ الواجهة تُكتب مرتين؛ يتطلب خبرة Swift.
- ⚠️ حجم الـ Framework على iOS ووقت البناء — يُدار بـ umbrella module واحد.
