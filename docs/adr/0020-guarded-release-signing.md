# ADR-0020: مسار توقيع الإنتاج المحروس عبر أسرار CI — بلا مفاتيح في المستودع

- **الحالة:** مقبول — قرار المالك 2026-11-10 (شريحة تجهيز التوقيع ضمن بوابة المرحلة 1 · تذكرة #31/T10 · #72)
- **التاريخ:** 2026-11-10
- **يُستكمل:** شروط الإغلاق في `RELEASE_GATE_PHASE1.md` (§5 — «تجهيز مسار التوقيع عبر أسرار CI عنصر برمجي متبقٍ»، و§7 — بناءات Play Internal/TestFlight الموقعة)

## السياق

بوابة المرحلة 1 تشترط بناءات موقعة لمساري Play Internal/TestFlight، والمستودع حتى الآن: **بلا `signingConfig` إنتاجي** (`release` يقع على fallback AGP — مفتاح debug الافتراضي للحزم) وبلا أي مفتاح Android/Apple (قاعدة صريحة: لا أسرار في المستودع). لا keystore إنتاج ولا بيانات Apple لدى المالك بعد — فالمطلوب جاهزية برمجية كاملة تُفعَّل بالأسرار حين تُوفر دون أي مساس بالوضع الراهن قبلها.

## القرار

### 1. التوقيع يُقرأ من متغيرات البيئة حصراً — الحارس fail-safe

`androidApp/build.gradle.kts` يقرأ أربعة متغيرات (`SILA_RELEASE_KEYSTORE_PATH` / `SILA_RELEASE_KEYSTORE_PASSWORD` / `SILA_RELEASE_KEY_ALIAS` / `SILA_RELEASE_KEY_PASSWORD`)، وتكوين `release` التوقيعي يُبنى **حصراً** حين تتوفر الأربعة جميعاً (لا فارغ ولا فراغ)؛ أي متغير غائب ⇒ لا تكوين ولا `signingConfig` ⇒ الوضع الراهن حرفاً (fallback AGP). لا قيم صلبة ولا ملفات مفاتيح في المستودع إطلاقاً.

### 2. CI يفك ترميز keystore من سر المستودع إلى `RUNNER_TEMP`

خطوة محروسة `if: secrets.SILA_RELEASE_KEYSTORE_BASE64 != ''` تفكّ keystore إلى `$RUNNER_TEMP/sila-release.keystore` (خارج المستودع) وتصدر مساره عبر `GITHUB_ENV`، وخطوة التجميع تمرر أسرار كلمة المرور/الاسم إلى متغيرات البيئة. **أسرار غائبة = سلوك CI بتطابق مع الحاضر** (قيم فارغة ⇒ الحارس يغلق) — فالدمج آمن قبل توفير المفاتيح.

### 3. بنية `benchmark` تبقى debug-signed بالتصميم

أداة القياس على العتاد المرجعي (ADR-0018) تتطلب تثبيتاً وقراءة آثار — توقيعها debug ثابت أياً كان توفر أسرار الإنتاج، فلا تتأثر منصة القياس بتدوير مفاتيح المتجر.

### 4. مسار Apple يبقى يدوياً خارج هذا القرار

توقيع iOS/TestFlight يتطلب شهادات Apple في keychain مضيف macOS وإدارة شهادات توزيع — خارج نطاق أسرار GitHub لهذه الشريحة، ويُنفَّذ يدوياً عند توفر بيانات Apple لدى المالك (موثق في §5).

## البدائل المرفوضة

- **`keystore.properties` محلي + gitignore:** نمط شائع لكنه يُدخل ملف سر على أقراص المطورين ويشيع الالتقاط العرضي؛ متغيرات البيئة أضمن الحدود (لا أثر ملفي).
- **توقيع CI بمفتاح debug مع رفعه لاحقاً:** يخالف شرط البوابة (بناءات متجر موقعة بمفتاح إنتاج).
- **انتظار المفاتيح قبل أي عمل:** يؤجل جاهزية برمجية بلا حاجة — نفس نمط «منصة القياس عند جهوز العتاد» في ADR-0018.

## الأثر

- تفعيل المسار لاحقاً = إنشاء 4 أسرار مستودع (`SILA_RELEASE_KEYSTORE_BASE64` + الثلاثية) حصراً — صفر تغيير كود.
- التحقق المحلي: بلا متغيرات ⇒ بناء مطابق للسابق؛ بمتغيرات تجريبية (keystore مؤقت `keytool` خارج المستودع) ⇒ `assembleRelease` موقعة إنتاجياً — والاثنان موثقان في PR الشريحة.
- `RELEASE_GATE_PHASE1.md` §5/§7 و`CHANGELOG.md` تحدثان الحالة: المسار **جاهز برمجياً** والتفعيل الفعلي ينتظر مفاتيح المالك.
