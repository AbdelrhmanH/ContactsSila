# 04 — دمج المكرر والتصنيف الذكي

> المرجع: [PRD §7–8](../PRD.md#7-دمج-الأسماء-المكررة)

## أ. دمج المكرر

### الخوارزمية
```text
1. لكل جهة اتصال: e164 لكل رقم، بريد lowercase، normalizedName.
2. تجميع (Union-Find):
   - نفس e164                → HIGH
   - نفس البريد               → HIGH
   - نفس normalizedName       → MEDIUM
   - JaroWinkler(name) ≥ 0.92 → LOW (اقتراح فقط)
3. استبعاد الأزواج في duplicate_dismissals.
4. ترتيب المجموعات: HIGH أولاً ثم الحجم.
```

**التطبيع العربي:** إزالة التشكيل والتطويل، `أ إ آ ٱ → ا`، `ة → ه`، `ى → ي`، `ؤ → و`، `ئ → ي`، توحيد المسافات، تحويل الأرقام الهندية لعربية، إزالة البادئات الشائعة عند المقارنة (د.، م.، أ.، Dr).

### الواجهة
- بطاقة في الرئيسية: "لديك 6 مجموعات مكررة".
- شاشة المكررات: لكل مجموعة بطاقة تعرض الأعضاء + **معاينة النتيجة** + [دمج] [ليست مكررة].
- زر "دمج كل المؤكدة (HIGH)".

### قواعد الدمج
| العنصر | القاعدة |
|---|---|
| الاسم | الأكمل (أكثر أجزاء) ثم الأطول |
| الأرقام/البريد/العناوين/المواقع | اتحاد بدون تكرار (بعد التطبيع) |
| الصورة | الأعلى دقة |
| الملاحظات | دمج بفاصل |
| التصنيف | غير UNCATEGORIZED، والأولوية FAMILY > EMERGENCY > WORK > FRIENDS > SERVICES |
| أرحام | للأقدم إنشاءً؛ `lastContactedAt` = الأحدث |
| المفضلة | true إن كان أي منها مفضلاً |
| النغمة | الموجودة إن وُجدت واحدة |

### معايير القبول
- [ ] لا فقدان لأي بيانات (اختبار خاصية: مجموع الأرقام الفريدة قبل = بعد).
- [ ] التراجع خلال جلسة الشاشة يعيد الوضع كما كان (لقطة محفوظة في Room).
- [ ] أندرويد: الدمج عبر `AggregationExceptions.TYPE_KEEP_TOGETHER` عندما تكون جهات الاتصال في حسابات مختلفة؛ وإلا تحديث واحدة وحذف الباقي.
- [ ] iOS: نسخة احتياطية vCard قبل الحذف وإعادة الكتابة.
- [ ] الفحص لـ 5000 جهة اتصال < 3 ثوانٍ على جهاز متوسط.

## ب. التصنيف الذكي

### المصادر والقواعد
| الإشارة | النتيجة | الثقة |
|---|---|---|
| كلمة عائلة (عمي، خالتي، ماما، جدو…) | FAMILY + اقتراح Relation | عالية |
| كلمة خدمة (دكتور، د.، صيدلية، سباك، كهربائي، ورشة، مطعم، شركة، مركز…) | SERVICES + professionId | عالية |
| كلمة طوارئ (إسعاف، شرطة، مطافي) أو رقم قصير معروف | EMERGENCY | عالية |
| الرقم موجود في الدليل السحابي (للمسجلين) | SERVICES | متوسطة |
| حقل الشركة غير فارغ | WORK | منخفضة |
| رقم أرضي/قصير | SERVICES | منخفضة |
| تفاعل متكرر طويل (سجل المكالمات) ⛔ غير متاح في المرحلة 1 — [ADR-0006](../adr/0006-call-log-strategy.md) مقبول بدون `READ_CALL_LOG` | اقتراح FAMILY/FRIENDS | منخفضة |

- القاموس **مضمّن في الحزمة حصراً** (`SmartFilterDictionary` — قرار Issue #28 الملزم: بلا Remote Config)، ويدعم العامية المصرية والخليجية والشامية والفصحى — تحديثه إصدار تطبيق، وكل مصطلحاته تُكتب بصيغة ما-بعد-التطبيع (عرف موثق يفحصه الاختبار).
- **حدود الكلمة:** المطابقة على مستوى الرموز (tokens) لا الأجزاء، لتجنب "محمد" ← "حمد".
- **التعلم المحلي:** رفض المستخدم لاقتراح (token→category) يقلل وزنه؛ القبول يزيده (`smart_filter_feedback`).

### الواجهة
- بعد Onboarding: إشعار/بطاقة "وجدنا 15 رقم خدمة، 8 من العائلة".
- شاشة مراجعة مقسمة حسب التصنيف المقترح، كل عنصر بـ Checkbox (المحدد افتراضياً: الثقة العالية فقط) ← "تطبيق".
- **التدريجي (مؤجَّل عن المرحلة 1 — قرار #16/#28 الموثق):** بعد مكالمة مع رقم غير مصنف ← Sheet خفيف "صنّف أحمد؟" مع 4 Chips + "لا تسأل عنه" — لا يُنفَّذ في T7 ولا يُحتسب من معايير قبول المرحلة 1.

### معايير القبول
- [ ] لا تصنيف تلقائي بدون موافقة (اقتراح فقط).
- [ ] احترام `excludeFromSmartFilter` و "لا تسأل عنه".
- [ ] عند قبول FAMILY مع Relation مقترحة ← فتح خيار إضافته لأرحام بوتيرة افتراضية.
- [ ] ~~السؤال التدريجي مرة واحدة يومياً كحد أقصى لكل رقم، وقابل للتعطيل~~ — مؤجَّل بقرار #16/#28 (خارج نطاق المرحلة 1).

## تحديثات T7 المنفذة (2026-11-08 — ADR-0013 · Issue #28)
- **كشف (§أ):** اتحاد أدلة union-find بثقة ثلاثية، رفض أزواج دائم في `duplicate_dismissals` بمفاتيح ثنائيات ثابتة، ورمز قصير/خط ساخن MEDIUM حصراً (لا يطوي فروع بنوك تتشارك خطاً). 5,000 جهة ≤ 3 ثوانٍ (معيار الأداء الرسمي — قياس مضيف + قياس جهاز في تقرير PR).
- **الدمج (§أ):** الناجي الأقدم إنشاءً؛ اتحاد الأرقام بالـ E.164 والبريد/العناوين/التواريخ/الحقول بالمفاتيح المطبَّعة؛ الملاحظات بفاصل `
—
`؛ أولوية التصنيف FAMILY>EMERGENCY>WORK>FRIENDS>SERVICES (ليست ترتيب التعداد)؛ النغمة الوحيدة تبقى والمتعددة ناغِم الناجي بعلم تعارض معروض في المعاينة. المسار الكامل في [ADR-0013](../adr/0013-merge-write-path.md).
- **التراجع:** جلسة شاشة المراجعة حصراً (شريط التراجع الموحد `SilaUndoBar`)؛ انتهاء الجلسة (24 ساعة حد مطلق) يتبعه المسح المؤجل المحروس باللقطة. انقطاع العملية = لا تراجع (موثق، مطابق للمواصفة).
- **الفلترة الذكية (§ب):** سلّم الثقة كما في جدول §ب (عائلة/خدمة/طوارئ = عالية، شركة/أرضي-قصير = منخفضة، لقب مهني = متوسطة)، `professionId` مع اقتراحات الخدمات، شاشة مراجعة مجمّعة بالتصنيف مع شفافية الدليل (المصطلح المطابق)، التحديد المسبق للثقة العالية حصراً، تطبيق مؤكد حصراً، «ليست هذه الفئة»/«لا تسألني مجدداً» يكتبان التغذية الراجعة/الاستثناء، وعدّ بطاقة الدخول = مطابقات القواعد تحت بوابة `smartFilterEnabled` حصراً (لا عدّ خام لكل غير المصنف — إصلاح agy F6).
- **FAMILY→أرحام (بلا اقتران ميزة):** عقد `ArhamKinshipLinker` داخل نطاق جهات الاتصال، تنفيذه جسر في جذر التركيب يدعو `upsertArhamInfo` **مباشرةً** (لا `UpdateKinshipUseCase` الذي يُخفق NotFound على المُصنَّف للتو — إصلاح agy F5) بوتيرة افتراضية غير-صفرية لكل قرابة.
- **المنصتان:** شاشتا مراجعة Compose (مسارات type-safe) ومرايا SwiftUI بنفس العقد المشترك ونفس مفاتيح الترجمة (24 `dup_*` + 17 `sf_*`).
