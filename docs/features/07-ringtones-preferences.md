# 07 — النغمات المخصصة والتفضيلات

> المرجع: [PRD §11–12](../PRD.md#11-النغمات-المخصصة)

## أ. النغمات المخصصة

### قصص المستخدم
- **US-07.1** أريد معرفة أن المتصل من العائلة دون النظر للهاتف.
- **US-07.2** أريد نغمة خاصة لشخص معين.

### معايير القبول
- [ ] الإعدادات ← النغمات: لكل تصنيف نغمة (افتراضي النظام). — نُفِّذ في T9 (قائمة النغمات من المنصة + نية `SetCategoryRingtone`).
- [ ] صفحة جهة الاتصال ← النغمة: نغمات النظام (`RingtoneManager.ACTION_RINGTONE_PICKER`) أو ملف صوتي (`ACTION_OPEN_DOCUMENT` + `takePersistableUriPermission`). — خارج نطاق المرحلة 1: تذكرة #59.
- [ ] الأولوية: نغمة جهة الاتصال > نغمة التصنيف > نغمة النظام. — مثبتة اختباراً في `GetEffectiveRingtoneUseCase`؛ بلا مستهلك إنتاجي بعد (تذكرة #59).
- [x] تغيير نغمة تصنيف ← `ApplyCategoryRingtoneWorker` يكتب `CUSTOM_RINGTONE` لكل الأعضاء الذين ليس لديهم نغمة فردية. — نُفِّذ في T9؛ واختباراتُ العامل أُضيفت (تذكرة #63 · S2-10): حقن إنشائي بلا Koin حقيقية، نجاحٌ موثق عدَّه في ناتج العمل (`pending_members`/`written_count`/`reason`)، تهيئة غائبة ⇒ `retry` لا نجاح صامت، صلاحية مرفوضة ⇒ تخطٍّ موثق، وإعادة تغيير الفئة ⇒ REPLACE بلا تراكم.
- [ ] تغيير تصنيف جهة اتصال ← تُطبق نغمة التصنيف الجديد (إن لم تكن فردية). — خارج المرحلة 1: تذكرة #59 (`UpdateContactCategoryUseCase` لا يلمس مسار النغمات).
- [ ] الملفات الصوتية المخصصة تُنسخ إلى `MediaStore.Audio` (Ringtones) لضمان بقائها. — خارج المرحلة 1: تذكرة #59.
- [x] iOS: الخيار يعرض شرحاً + زر «فتح تطبيق جهات الاتصال» — نُفِّذ (S1-16 — تذكرة #65): مخطط `contacts` مسجَّل في `Info.plist` فيجيب `canOpenURL` فعلاً مع بقاء احتياط إعدادات النظام لحالة غياب التطبيق؛ وحالة حوار التوجيه (`showRingtoneGuidanceDialog` + زوجَ Show/Dismiss) أزيلت نهائياً — بلا مستهلك على أي منصة، والإرسالان تحت الإطار نفسه كانا يهلكان كل أعلامهما فوراً.

### توافقة الأرحام بين المنصتين (قرار تذكرة #70)
الموعد وساعات الهدوء والحد اليومي **قابلة للتحرير على المنصتين**: الشاشة المشتركة (Compose) عبر صف الوقت وحوار الساعات الهادئة، وiOS عبر شاشة إعداداتها الأصلية (`SettingsView.swift`) — منتقا ساعة/دقيقة لوقت التذكير ومنتقا بداية/نهاية لساعات الهدوء يرسلان النيتين المشتركتين (`SetArhamNotificationTime`/`SetQuietHours`) وغلاف `SettingsTimeFormatting` مطابق لدلالة Compose. **فارق تفاعلي معلن (شكلي لا دلالي):** أندرويد يُجوب الساعة دورياً ويصفّر الدقيقة (محرّر مبسّط)، وiOS منتقي عجلة مستقلان (ساعة 0–23 + دقيقة 0–59) — الدلالة البيانية واحدة، والمجدولة تُعاد فورياً على المنصتين (تذكرة #71). **مكان القرار (S2-12 — تذكرة #69):** دورات أندرويد (السّمة، لفّ الساعة، الحد اليومي 1..5) قرارها في `SettingsViewModel` عبر النى `CycleThemeMode`/`CycleArhamNotificationHour`/`CycleArhamMaxPerDay` بقراءة التفضيل الحي حصراً — صفوف Compose ترسل النية فحسب (شاشة إسناد صرف).

- [ ] أوقات الهدوء تدعم الفترات العابرة لمنتصف الليل.
- [x] تغيير وقت التذكير يعيد جدولة الإشعارات — نُفِّذ (تذكرة #71 · ADR-0016): نيايا الميزة/الوقت/ساعات الهدوء تُدفع فور نجاح كتابتها عبر منفذ إعادة الجدولة (`ArhamReminderSchedulingPort`) إلى مجدول المنصة (أندرويد `ArhamReminderDispatch` · iOS `IosArhamReminderDispatch` بعقد `cancelPending` عند التعطيل) — بلا انتظار إقلاع لاحق، والقرار في `PlanArhamDailyNotificationUseCase` حصراً.

### النسخ الاحتياطي والاستعادة (Backup & Restore)

**ما يُصدَّر:**
| البيانات | مُضمّنة | ملاحظات |
|---|---|---|
| التصنيفات لكل جهة اتصال | ✅ | `contactId → category` (مرتبط بـ `lookupKey` لإعادة الربط) |
| بيانات أرحام | ✅ | القرابة، الوتيرة، المناسبات |
| الوسوم المخصصة | ✅ | Tags |
| التفضيلات | ✅ | كل DataStore |
| نغمات التصنيفات | ✅ | URI فقط (ليس ملف الصوت) |
| سجل النزاعات | ✅ (قراءة-حصراً) | يُصدَّر من Room حصراً (SSOT) عبر استعلام DAO مرتّب تنازلياً على `updatedAt` (S1-5 — تذكرة #61): الحقول الثلاثة في الحمولة `serviceCloudId`/`description`/`status` — والقراءة **مستقلة عن مسار الكتابة** الذي بقي خارج المرحلة 1 («توثيق نزاع» — المرحلة 2؛ تعايرة التذكرة). الجدول يُتبنّى آلياً من قاعدة قديمة (ADR-0011) فقد يحمل صفوفاً فعلية قبل الكاتب المقبل. **الاستعادة لا تستهلك نزاعات الحمولة بعد** — تُفعَّل مع كاتب «توثيق نزاع» ذاته (المرحلة 2 ذاتها)؛ ومعاينة الاستعادة تعرض عدّاد النزاعات على المنصتين بنصوص مترجمة |
| جهات الاتصال نفسها | ❌ | تُقرأ من دفتر الهاتف — لا حاجة لنسخها |
| سجل المكالمات | ❌ | يبقى محلياً في Room ولا يُصدَّر ([ADR-0006](../adr/0006-call-log-strategy.md): لا `READ_CALL_LOG`) |

**الصيغة:**
```json
{
  "version": 1,
  "exportedAt": "2026-01-15T10:00:00Z",
  "appVersion": "1.2.0",
  "categories": [
    { "lookupKey": "abc123", "displayName": "أحمد", "category": "FAMILY" }
  ],
  "arham": [ { "lookupKey": "abc123", "relation": "UNCLE_PATERNAL", "frequency": "MONTHLY" } ],
  "tags": [ { "lookupKey": "abc123", "tags": ["سباك", "السويس"] } ],
  "preferences": { "theme_mode": "DARK", "language": "ar", ... },
  "categoryRingtones": { "FAMILY": "content://media/..." },
  "disputes": [{ "serviceCloudId": "srv_1", "description": "تأخر في الموعد", "status": "OPEN" }]
}
```

**الأمان:**
- الملف مشفّر بـ **AES-256-GCM** مع مفتاح مشتق من كلمة مرور المستخدم (PBKDF2). قرار المحرك اليدوي وقفله بمتجهات KAT: [ADR-0017](../adr/0017-hand-rolled-backup-crypto-engine.md).
- الامتداد: `.sila.backup` — يُحفظ في مجلد التنزيلات أو يُشارك. (التطبيق الفعلي: إحالة ملفات النظام SAF على أندرويد ومشاركة على iOS — PR #73)
- حجم الملف المتوقع: < 1 MB لـ 5000 جهة اتصال.

**الاستعادة:**
- [x] إدخال كلمة المرور ← فك التشفير ← معاينة المحتويات (عدد التصنيفات/الأقارب/الوسوم/النغمات/سجل النزاعات — بنصوص مترجمة على المنصتين: والمفاتيح `SettingsStrings` على Compose ومفتاح `settings_preview_counts` على iOS؛ تذكرة #61).
- [x] الربط بـ `lookupKey` — إن لم يوجد تطابق → حوار «نتيجة الاستعادة» يعرض السجلات غير المطابقة مع الربط اليدوي: بحث بالاسم/الرقم يقرأ **من Room حصراً** (`searchLinkCandidates`؛ أقل من حرفين لا يستهلك بحثاً)، وكل سجل يربط بجهة مختارة عبر `linkUnmatchedEntry` (تصنيف + صلة رحم؛ الطبقة من `Relation.layer`، والتكرار يبدأ `OCCASIONS` المحايد؛ `false` عند غياب جهة الهدف أو خلوه من تصنيف وصلة معاً). PR #62.
- [x] خيار: "دمج مع البيانات الحالية" أو "استبدال بالكامل".
- [x] لا تُستعاد التفضيلات تلقائياً — يُسأل المستخدم.
- [x] **الذرّية كل-أو-لا-شيء** (S1-1/S3-22 — تذكرة #60 · [ADR-0015](../adr/0015-atomic-restore-transaction-passage.md)): كل كتابات التصنيفات/الأرحام/الوسوم (شطف REPLACE + الكتابات) في **معاملة Room واحدة** عبر ممرّ `ClassificationRestoreRunner` فوق `LocalSilaDatabase` — انهيار أو انقطاع في أي نقطة يُرجِع القاعدة كما-كانت (لا «محوّة دون استعادة» ولا كتابة جزئية). غياب جهة يُكتشف داخل المعاملة يُدرج ضمن السجلات غير المطابقة (حوار النتيجة) بلا كتابة.
- [x] **دلالة `restorePreferences` الموثّقة:** `true` يستعيد تفضيلات الحمولة **ونغمات التصنيفات `categoryRingtones` معها** (سلوك كان في الكود منذ T9 بلا تدوين — وُثّق الآن). تفضيلات DataStore تُنفَّذ **بعد نجاح المعاملة حصراً** — فشل الاستعادة الذرّية يبقي التفضيلات بلا مساس (`BackupErrorKind.GENERIC` عند الفشل).
- [x] عهد الدلالة المحفوظ: شطف REPLACE يمس التصنيف/الوسوم/الأرحام لا التواريخ ولا الأطفال والحقول القياسية؛ إسناد أرحام يُلزم التصنيف `FAMILY`؛ تواريخ الحمولة تستبدل غير-الفراغة حصراً؛ مدخلات الوسوم غير-المطابقة لا تُعرض في الحوار (سلوك سابق).
